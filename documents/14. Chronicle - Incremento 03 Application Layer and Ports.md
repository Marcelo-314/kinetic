# Chronicle - Incremento 03 Application Layer and Ports

**Fecha:** 2026-04-19  
**Estado:** Implementado  
**Objetivo del incremento:** incorporar la capa de aplicación y los puertos mínimos del sistema, manteniendo el dominio puro y preparando el terreno para persistencia y runtime en incrementos posteriores.

## 1. Alcance implementado

En este incremento se agregó la primera versión funcional de la capa `application`, junto con los contratos de salida mínimos del sistema.  

El objetivo fue dejar resuelta la coordinación entre:

* dominio puro
* `TransitionEngine`
* puertos de persistencia e infraestructura

sin implementar todavía:

* adapters JPA
* controllers REST
* runtime real
* workers
* lease manager concreto

## 2. Ajuste técnico en dependencias de test

Se revisó la configuración de dependencias de test en `pom.xml` y se volvió a usar:

* `spring-boot-starter-test`

como dependencia estándar de testing.

Esto simplifica el build y evita microconfiguración innecesaria en esta etapa.  

Observación:

* en este entorno/JDK sigue apareciendo un warning de Mockito por self-attach del agent
* no rompe la compilación ni la suite
* no se agregó configuración extra para mitigarlo en este incremento, para mantener el cambio acotado

## 3. Refinamiento menor del dominio

Se ajustó la semántica inicial de `version` en `ProcessAggregate`.

### Decisión aplicada

Ahora:

* `ProcessAggregate.pending(processId)` crea el agregado con `version = 1`

### Justificación

Esto queda mejor alineado con el contrato externo aprobado, donde `ProcessResource.version` parte de `1` y se espera una revisión monotónica del agregado.

### Cobertura agregada

Se incorporó:

* `ProcessAggregateTest`

para verificar:

* inicio en versión `1`
* rechazo de versiones menores a `1`

## 8. Responsabilidad de los use cases

Los casos de uso:

* coordinan puertos
* cargan/guardan el agregado y objetos asociados
* invocan el `TransitionEngine`
* persisten la información mínima derivada
* registran actividad básica

Los use cases **no**:

* dependen de Spring
* usan JPA
* usan adapters concretos
* contienen lógica de framework

## 9. Semántica implementada por use case

### 9.1. `CreateProcessUseCase`

Responsabilidades implementadas:

* valida request mínima
* valida existencia de `source_folder` vía `FileSourcePort`
* resuelve `selected_files`
* crea:
  * `ProcessAggregate` inicial en `PENDING`
  * `ProcessPlan`
  * `AuthorizationInfo`
  * `ProgressSnapshot`
  * `ExecutionControlFlags`
  * `ActivityLogEntry`

### 9.2. `AuthorizeProcessUseCase`

Responsabilidades implementadas:

* carga el proceso por `process_id`
* delega transición a `TransitionEngine`
* persiste agregado actualizado
* actualiza `AuthorizationInfo` a `AUTHORIZED`
* fija `started_at` en `ProgressSnapshot`
* registra actividad

### 9.3. `PauseProcessUseCase`

Responsabilidades implementadas:

* carga el proceso
* ejecuta `PauseProcess` en el `TransitionEngine`
* persiste el agregado con intención de pausa
* sincroniza `ExecutionControlFlags`
* registra actividad

### 9.4. `ResumeProcessUseCase`

Responsabilidades implementadas:

* carga el proceso
* ejecuta `ResumeProcess`
* persiste el agregado en `RUNNING`
* limpia flags de control
* registra actividad

### 9.5. `StopProcessUseCase`

Responsabilidades implementadas:

* carga el proceso
* ejecuta `StopProcess`
* persiste el agregado
* si la transición queda terminal:
  * crea `TerminalInfo`
  * limpia flags
  * registra `PROCESS_STOPPED`
* si la transición queda en intención:
  * conserva `RUNNING`
  * marca `stop_requested`
  * registra `STOP_REQUESTED`
