# Chronicle - Incremento 01 Bootstrap

**Fecha:** 2026-04-19  
**Estado:** Implementado  
**Objetivo del incremento:** bootstrap del proyecto y estructura hexagonal mínima, sin lógica de negocio.

## 1. Alcance implementado

En este incremento se dejó preparado el esqueleto inicial del proyecto Chronicle respetando la documentación del repositorio como fuente de verdad, en particular:

* OpenAPI como fuente de verdad del contrato HTTP público
* arquitectura hexagonal por paquetes
* uso de Spring Boot solo como framework de composición/bootstrap
* dominio desacoplado de Spring/JPA/HTTP
* stack técnico acordado: Java 21, Maven, Spring Boot 3.x, H2 in-memory

## 2. Cambios realizados

### 2.1. Build y dependencias

Se ajustó `pom.xml` para dejar únicamente el stack mínimo requerido para este incremento:

* `spring-boot-starter-web`
* `spring-boot-starter-data-jpa`
* `h2`
* `spring-boot-starter-test`

También se corrigió el proyecto para usar:

* `groupId`: `com.chronicle`
* `java.version`: `21`
* `Spring Boot`: `3.5.0`

Se eliminaron starters y piezas que no correspondían al alcance del incremento.

### 2.2. Bootstrap de Spring Boot

Se creó la clase principal:

* `com.chronicle.bootstrap.ChronicleApplication`

Esta clase queda ubicada en la capa `bootstrap`, alineada con la separación arquitectónica acordada.

### 2.3. Estructura hexagonal mínima

Se dejó visible la estructura base por paquetes:

* `com.chronicle.domain`
* `com.chronicle.application`
* `com.chronicle.adapters.in.web`
* `com.chronicle.adapters.out.persistence`
* `com.chronicle.adapters.out.filesystem`
* `com.chronicle.adapters.out.runtime`
* `com.chronicle.bootstrap`

En esta etapa se materializó la estructura sin introducir implementaciones funcionales.

### 2.4. Configuración base

Se ajustó `src/main/resources/application.yaml` con una configuración mínima para:

* nombre de aplicación
* datasource H2 in-memory
* habilitación de consola H2
* JPA base sin DDL automático
* `open-in-view: false`
* `graceful shutdown`

## 3. Testing

Se mantuvo un test mínimo de contexto:

* `com.chronicle.bootstrap.ChronicleApplicationTests`

Este test verifica únicamente que el contexto Spring Boot pueda levantar con la configuración actual.

## 4. Verificación ejecutada

Se ejecutó:

```bash
mvn test
```

Resultado:

* build exitoso
* contexto Spring levantando correctamente
* test de contexto pasando

## 5. Restricciones respetadas

En este incremento **no** se implementó:

* lógica de negocio
* `TransitionEngine`
* casos de uso reales
* controllers funcionales
* runtime dispatcher
* lease manager
* workers
* entidades JPA de dominio
* lógica de lifecycle en controllers o configuración
* Spring Batch
* Spring State Machine

## 6. Resultado

El proyecto quedó listo para los siguientes incrementos con una base pequeña, compilable y revisable:

* arranca
* compila
* pasa `mvn test`
* expone la estructura hexagonal acordada
* no introduce lógica prematura
